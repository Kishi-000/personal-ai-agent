
# Personal AI Agent

個人の目的・条件に応じて、問題の整理から情報収集、候補の検証、意思決定支援までを行うAIエージェントのMVPです。

## 1. プロジェクトの目的

生成AIを単なる質問応答ツールとして利用するのではなく、問題解決の一連の工程を支援する仕組みとして構築することを目的としています。

ユーザーの要望を構造化し、不足情報の確認、必要に応じたWeb調査、必須条件の検証を行い、判断根拠を含む最終回答を生成します。

また、AIの出力をそのまま採用せず、独立した検証工程を設けることで、回答の信頼性向上を図っています。


## 2. 実装済み機能

1. **問題理解・構造化**
   - ユーザーの目的・要望・制約条件をJSON形式で整理
   - 必須条件と希望条件を区別

2. **追加質問の制御**
   - 意思決定に必要な不足情報を確認
   - 不要な質問を抑制
   - 質問数の上限を管理し、回答内容を再評価

3. **Web調査の必要性判定**
   - 問題の性質に応じてWeb調査の要否を判断
   - 必要な場合のみWeb検索を実行

4. **候補探索・条件検証**
   - 調査結果から候補を抽出
   - 必須条件ごとに適合状況を検証
   - PASS / FAIL / UNKNOWNで判定し、不明な情報を無条件に適合扱いしない

5. **独立した検証工程**
   - 最終回答の前に、別のAI処理で調査結果と条件判定を確認
   - 検証結果を最終回答に反映

6. **最終回答の生成**
   - 候補の比較結果と判断根拠を整理
   - 条件未達・未確認事項を明示
   - ユーザーの意思決定を支援

## 4. システム構成

処理の基本的な流れは以下のとおりです。

```text
ユーザー入力
    ↓
問題理解・JSON構造化
    ↓
追加質問の必要性判定
    ↓
必要に応じて追加質問・再評価
    ↓
Web調査の必要性判定
    ├─ 不要 → 最終回答生成
    └─ 必要
         ↓
       Web検索・候補探索
         ↓
       必須条件の検証
         ↓
       独立したAI検証
         ↓
       検証結果を反映
         ↓
       最終回答生成
```


## 5. 実行方法

### 必要な環境

- Python 3.13
- OpenAI APIキー
- インターネット接続

### セットアップ

1. リポジトリを取得します。

   ```bash
   git clone https://github.com/Kishi-000/personal-ai-agent.git
   cd personal-ai-agent
   ```

2. OpenAI SDKをインストールします。

   ```bash
   python -m pip install openai
   ```

3. 環境変数 `OPENAI_API_KEY` に自身のAPIキーを設定します。

   APIキーはソースコードに直接記載せず、環境変数で管理してください。

4. プログラムを実行します。

   ```bash
   python 00_main.py
   ```

5. 画面の案内に従って、目的・要望・条件を入力します。

### 注意事項

- OpenAI APIの利用には、利用量に応じた料金が発生する場合があります。
- Web調査の結果には誤りや未確認情報が含まれる可能性があります。
- 本プログラムは開発・検証段階のMVPであり、出力結果の正確性を保証するものではありません。


## 6. 検証実績

MVPの動作確認として、複数の入力条件を用いた回帰テストを実施しました。

### 検証例：スマートフォンの購入候補比較

以下の条件を持つユーザーの意思決定支援を想定しました。

- 日本国内で新品購入できるSIMフリーAndroid
- 予算：税込10万円以内
- ストレージ：256GB以上
- おサイフケータイ対応
- 防水防塵対応

検証では、候補ごとに必須条件への適合状況を確認しました。

特に、情報が不足している候補については、推測でPASSとせず、UNKNOWNとして扱う動作を確認しました。

また、独立したAI検証工程からの指摘を最終回答に反映し、未確認事項を明示できることを確認しました。

### 検証上の限界

- 独立したAI検証は、主に調査結果・判定内容の整合性を確認するものであり、外部情報源をすべて独立に再検証する仕組みではありません。
- 必須条件の判定は現段階ではAI処理が中心であり、Pythonによる決定論的な再検証は今後の改善課題です。
- 調査時点と実際の購入時点で、価格や販売状況が変化する可能性があります。


## 7. 今後の改善予定

本プロジェクトはMVPとして基本的な処理フローを実装した段階です。今後は以下の改善を検討しています。

- **条件検証の強化**：Pythonによる決定論的なPASS / FAIL / UNKNOWN判定
- **情報源の検証**：参照URL・取得日時・根拠情報の記録と確認
- **テストの自動化**：代表的な入力条件を用いた回帰テストの整備
- **保守性の向上**：処理のモジュール分割、例外処理・ログ管理の改善
- **ユーザー体験の改善**：入力方法や結果表示の改善

なお、これらは今後の検討事項であり、現時点での実装済み機能とは区別しています。
